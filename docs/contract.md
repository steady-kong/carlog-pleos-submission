# 데이터 계약과 이관 전략

이벤트 교환 초안은 `event.schema.json` v1이다. 앱은 이벤트 상세에서 이 규격의 JSON 텍스트를 공유할 수 있다. 파일 저장과 가져오기는 아직 구현하지 않았다. 각 차량과 기록은 UUID를 사용하며 웹에서 기존 차량 ID를 유지하거나 명시적으로 매핑한다. 차량 ID가 다르면 자동 병합하지 않는다. 이벤트 UUID를 중복 방지 키로 쓰고 같은 ID에 내용이 다르면 무조건 덮어쓰지 않고 충돌로 처리한다. 신호는 이벤트 ID, 개별 시각, 이름을 키로 한다. ISO 8601 UTC로 교환하고 앱 내부 시간은 Unix epoch milliseconds다. 거리는 km, 연료는 L, 금액은 정수 KRW, 좌표는 WGS84 도, 비율은 %다. 수집 출처와 완료 상태를 보존한다. 발생 시점 스냅샷은 각 신호에서 발생 시각 이전 가장 가까운 값이며 각 원래 시각을 보존한다.

기존 PWA 백업은 `app=carlog`, `schemaVersion=1` 및 `data.vehicles`, `fuelLogs`, `maintenanceLogs`, `expenseLogs`, `odometerReadings`, `maintenanceSchedules`를 사용한다. 차량 ID, 날짜, 주행거리, 주유량/가득 여부/비용, 정비 항목과 비용, 지출 분류와 금액을 각각 명시적으로 매핑한다. 현재 앱의 간소화된 RecordEntity는 정비의 다중 항목, 소프트 삭제, 수정 시각 등을 보존하지 못하므로 무손실 PWA 교환에 사용하면 안 된다. PWA 백업 import는 기존 데이터를 전부 대체하므로 앱에서 호출하거나 수정하지 않는다. 실제 이관은 원본 백업 보존, 별도 변환기와 검증, 충돌 미리보기, 테스트 복원 후 도입한다.

향후 Sync 인터페이스는 로컬 UUID, updatedAt, deletedAt 및 서버 revision을 포함하는 변경 묶음을 업로드하고 cursor로 서버 변경을 받도록 설계한다. 사용자 인증, 동의, 충돌 해결, 재시도와 삭제 전파를 명세하기 전까지 Supabase에 연결하지 않는다. 위치·차량 정보 공유에는 명시적 동의와 삭제 정책이 필요하다.
