# 공모전 Mock 시연

이벤트 탭의 기록·마이크 아이콘으로 기능을 구분하고, 버튼 아래에서 요청·사후 수집·완료 상태를 확인한다. 남은 시간은 근사치이며, 시간이 0이 되어도 실제 저장 상태가 갱신되기 전에는 완료로 표시하지 않는다. 차량 관리의 연료·배터리 막대는 Mock 관측값이고, 지출 추이는 기록이 있는 두 달 이상에만 표시된다. 소모품 계산용 시뮬레이션·추정 주행거리 체크박스는 `차량 테스트 도구 펼치기`에 있다.

## 시연 전 준비·리허설 체크리스트

- [ ] 시연용 기기/환경에 앱 설치와 실행을 미리 마친다. 이 저장소 문서에서 확인된 준비 절차는 debug APK 빌드(`./scripts/gradle.sh :app:testDebugUnitTest :app:assembleDebug`)와 결과 경로(`app/build/outputs/apk/debug/app-debug.apk`)까지다. 전용 AVD 시연용 `scripts/pleos-demo.sh`는 창 없는 모드에서 설치·실행만 확인했다. 워크스테이션 그래픽 창에서 Carlog 화면 표시를 확인했다. 전체 수동 시연과 실제 Pleos 기기는 사전 확인이 필요하다. AVD는 읽기 전용이므로 종료하면 시연 중 입력이 보존되지 않는다.
- [ ] 앱의 `이벤트` 탭에서 `시뮬레이션 데이터 · MOCK` 및 신호 상태를 확인한다. 시연은 정차 상태에서 진행한다.
- [ ] 이벤트를 기록하기 전에 앱을 켜 둔 상태로 최소 60초 기다려 이전 구간 신호가 쌓이게 한다. 실제 전용 AVD 계측 시험은 발생 전 59초 이상과 발생 후 60초 완료를 확인했으며, 정확한 60초 표본이나 연속 수집을 보장하지 않는다.
- [ ] `지금 이벤트 기록`을 눌러 기본 분류 `일반 이벤트`로 순간을 기록하고 `수집 중`을 확인한다. 필요하면 타임라인에서 상세를 열어 분류와 메모를 나중에 입력한다. 이후 앱을 종료하거나 수집을 중단하지 않고 60초 기다려 `수집 종료`를 확인한다.
- [ ] 최근 이벤트에서 상세를 열어 요약과 주요 관측값을 보고, `상세 데이터 보기`에서 전후 표본과 그래프를 확인한다. 정비 결과와 리포트까지 실제 시연 환경에서 미리 리허설한다.
- [ ] 지도 앱 열기, 파일 공유/저장, 실차 신호, Pleos 기기 설치·실행은 이 절차의 검증 범위에 포함되지 않는다. 필요한 경우 해당 시연 환경에서 따로 확인하고, 검증 전에는 동작을 약속하지 않는다.

## 시연 순서

1. `이벤트` 탭에서 `시뮬레이션 데이터 · MOCK` 표기와 신호 상태를 확인한다.
2. `차량 관리` 탭에서 `기록 추가`를 눌러 주유 기록 두 건과 소모품 교체 주기를 입력하고 저장한다. 연비와 `교체 예정` 표시를 확인한다.
3. `차량 관리`에서 자동 주행거리 기반 교체 판정을 보여줄 때는 `시뮬레이션 주행거리를 교체 판정에 적용`을 선택하고 판정 기준에 시뮬레이션 적용이 표시되는지 확인한다. 연료와 EV 배터리 신호는 별도 시뮬레이션 신호다.
4. 차량을 정차한 시연 환경에서 `지금 이벤트 기록`을 누른다. 기본 분류는 `일반 이벤트`이며 최근 60초 신호 표시는 가장 오래된 관측 신호의 나이를 보여주고 연속 수집을 뜻하지 않는다. 자유 발화를 메모로 남기려면 `음성 기록`을 누르고 설치된 Android 음성 인식 앱에 내용을 말한다. 이벤트 시각은 인식 후 차량 사용 상태를 확인한 시점이므로 인식 완료보다 늦을 수 있다.
5. 화면의 `수집 중` 상태를 확인하고 앱을 켜둔 채 60초 기다린 뒤 이벤트의 `수집 종료` 상태를 확인한다. 시작 후 60초 안에 기록하면 이벤트 전 구간은 그만큼 짧다.
6. `이벤트`의 최근 이벤트를 열어 주요 관측값과 위치를 확인한다. `상세 데이터 보기`를 펼치면 실제 기록 시각 범위와 신호별 그래프·표본을 볼 수 있다. 발생 시점에 가까운 표본의 시각·값과 측정 시각/수신 시각 구분을 설명한다.
7. 상세의 `분류·메모 수정`으로 사후 분류와 메모를 입력한다. `차량 관리` 탭의 `기록 추가`에서 정비와 이벤트를 연결한 뒤 해당 이벤트의 정비 참고 리포트를 연다. Mock 수집 제어와 이벤트 JSON 가져오기는 이벤트 탭의 `테스트 도구 펼치기` 안에 있다.

## 화면 설명과 제한

이벤트 상세의 주요 정보는 발생 시점 또는 그 이전에 마지막으로 기록된 값이다. 정확히 발생 순간의 측정값이나 연속 수집을 뜻하지 않는다. `상세 데이터 보기`에서는 신호 이름·단위·시각 종류별 관측값과 그래프를 확인한다. 관측값 요약은 최대 20개이며 더 많은 신호의 요약은 정비 참고 리포트에서 확인한다.

표본 목록은 전·후 각각 최대 5개다. JSON 내보내기 제한을 통과하면 전체 표본을 확인할 수 있다. 신호가 많으면 그래프는 시간 구간별 첫·마지막·최솟값·최댓값으로 축약되고 화면에 표시 수가 안내된다. 기록 시각 범위도 연속 수집을 보장하지 않는다.

위도와 경도가 같은 이벤트의 같은 시각에 기록되고 단위와 범위가 유효하며 지도 앱이 있으면 발생 전 마지막 좌표를 열 수 있다. 좌표 시각이 다르면 합쳐서 표시하지 않는다. 리포트의 차량 정보는 미리보기를 연 시점의 현재 등록 정보이며 이벤트 당시 정보와 다를 수 있다. Pleos 이미지에서 문서 선택기의 실제 표시는 검증하지 않았다.

전용 AVD 화면 시험에서 같은 시각의 유효한 Mock 좌표는 지도 버튼을 표시하고 좌표 시각이 다르면 안내만 표시됨을 확인했다. 외부 지도 앱을 실제로 실행하는 시험은 아니다.

별도 전용 AVD 시험에서는 고정 Mock 좌표를 `geo:` URI로 만들어 별도 UID의 시험 앱에 명시적으로 전달했다. 실제 지도 앱 선택기나 지도 앱별 호환성은 확인하지 않았다.

지도 앱을 찾지 못하거나 실행이 제한되면 앱은 지도 화면을 열 수 없다고 안내한다. 두 예외 처리 경로는 AVD에서 모의 시험했으며 실제 안내의 시각적 표시는 확인하지 않았다.

리포트는 `닫기`, 이벤트 상세는 `이벤트 목록으로` 버튼으로 돌아갈 수 있다. Android Automotive 차량은 시스템 뒤로 가기 수단을 제공하지 않을 수 있으므로 앱 내 버튼을 사용한다. [Android Automotive 안내](https://developer.android.com/training/cars/platforms/automotive-os)는 앱 내부 이동 수단을 제공하도록 안내한다.

주유 두 건과 소모품 주기를 입력하는 화면 계측 시험에서 연비와 교체 예정 문구의 생성을 확인했다. 입력 저장 성공 시 앱이 포커스를 해제하도록 개선한 후에는 시험 코드에서 별도 포커스 조작 없이 연비 문구까지 스크롤해 표시되는 것도 확인했다. 최초 시도의 가시성 실패 원인과 실제 사용자의 키보드 표시·숨김은 확인하지 않았으며, 교체 예정 문구는 존재만 검증했다. 실제 시연 화면에서 스크롤과 가시성을 별도로 확인한다.

이벤트와 정비 결과 연결은 운전자와 정비사의 의사소통을 돕는 참고 기능이다. 제조사 품질 분석은 별도 협력과 사용자 동의가 확보된 이후의 가능성이다. 현재 구현된 기능이 아니다. Pleos 전용 에뮬레이터에서는 Mock 앱과 별도 SDK 실험 모듈을 검증했다. 실차 연결과 SDK의 앱 통합은 아직 검증하지 않았다.

전용 AVD에서 실제 경과 시간으로 Mock 신호를 이벤트 전 최소 59초 모으고 발생 후 60초 완료까지 기다린 화면 계측 시험이 통과했다. 저장된 표본은 발생 전·후 각각 58초 이상 떨어진 신호를 포함했고 리포트의 발생 후 관측값 표시를 확인했다. 이는 관찰된 표본의 범위이며 연속 수집이나 정확한 ±60초 표본 확보를 의미하지 않는다.

2026-11-06 재시험에서는 트랜잭션 기반 리포트에 신호별 관측 범위와 연결 정비 결과가 나타나는 것도 확인했다. 정비 기록은 시험 코드가 직접 생성했으므로 정비 입력 화면 전체를 검증한 것은 아니다.

별도의 전용 AVD 화면 시험에서는 미리 생성한 오래된 이벤트를 정비 입력 화면에서 직접 선택하고 정비 내용과 결과를 저장해 리포트에서 확인했다. 이 시험은 앞의 실제 2분 수집 시험과 별도로 실행했다.

이후 확장한 2분 시험은 Mock 이벤트의 전후 표본을 실제 경과 시간으로 수집한 다음, 같은 실행에서 정비 입력 화면으로 해당 이벤트를 선택하고 결과를 저장해 리포트에서 확인했다. 저장된 표본의 시간 범위를 확인한 시험이며 실차 데이터나 연속 수집을 입증하지 않는다.

2026-11-08 이 확장 시험을 Pleos 전용 AVD에서 다시 실행해 1개 통과했다. 인메모리 Room을 사용했으며 시험 종료 후 에뮬레이터와 Gradle 프로세스가 남아 있지 않았다.

2026-11-09 이벤트 저장 복구와 상세 화면 변경 후 같은 선택형 시험이 다시 통과했다. Mock과 인메모리 Room을 사용한 결과다.

이후 확장한 통합 시험에서는 동일한 실행에서 주유 두 건과 소모품 주기를 화면으로 입력하고 연비·교체 예정 표시를 확인한 뒤, Mock 이벤트 전후 표본과 그래프, 정비 결과 연결·리포트까지 확인했다. 지도 앱 열기와 파일 공유는 이 시험 범위에 없다.

이 약 2분짜리 시험은 자원 사용을 줄이기 위해 일반 테스트에서는 건너뛴다. 전체 구간 재검증이 필요할 때만 전용 AVD 시간 제한과 함께 실행한다.

```bash
CARLOG_PLEOS_MAX_SECONDS=240 scripts/pleos-emulator-test.sh :app:connectedDebugAndroidTest \
  '-Pandroid.testInstrumentationRunnerArguments.class=kr.carlog.pleos.FullEventDemoTest' \
  -Pandroid.testInstrumentationRunnerArguments.fullEventDemo=true
```

현재 Activity는 Distraction Optimization을 선언하지 않는다. 앱은 Android Automotive `CarUxRestrictions`를 관찰하며 제한이 있거나 상태를 확인할 수 없으면 조작을 차단한다. 제한이 없다는 응답도 안전한 정차의 증거는 아니다. [Pleos 주행 제한 정책](https://document.pleos.ai/en/docs/pleos-only/vehicle-app-planning-guide/driving-restiction-policy)에 따라 주행 중 화면·버튼·음성 호출을 사용할 수 있다고 주장하지 않는다. 실차 연동 시 허용되는 앱 유형과 UI, 플랫폼 제한 적용, 별도 심사 및 입력 수단을 확인해야 한다.

전용 AVD v2.1.0에서 공식 문서의 `cmd hmg_car_service --service drivingstate driving_regulation on`은 서비스가 없어 종료 코드 20을 반환했다. 따라서 이 이미지에서는 해당 명령으로 제한을 활성화하지 못했고 화면 차단 여부를 검증하지 못했다. 분리된 앱 ID의 선택적 계측 시험은 서비스가 없으면 건너뛰며, 기본 테스트에서는 실행되지 않는다.

별도의 Google Android Automotive API 33 AVD에서는 [Android 공식 에뮬레이터 안내](https://developer.android.com/training/cars/testing/emulator)의 주행 상태 시뮬레이션을 사용했다. 시험 앱에서 기어와 속도를 바꾸자 제한 상태가 `DO: true`, `UxR: 255`로 바뀌었고 Activity는 `RESUMED`에서 `STARTED`로 전환됐다. 별도 시험에서 제한 전 시작한 Mock 이벤트의 신호 수는 4초 동안 5개에서 25개로 증가했고 상태는 `collecting`이었다. 주차 상태로 복원한 뒤 `DO: false`를 확인했다. 이는 해당 시험에서 앱 프로세스가 유지되는 동안 Mock 수집이 계속된 관찰이며, 화면 가림의 시각적 확인이나 장시간 백그라운드·Pleos 전용 이미지·실차 동작을 보장하지 않는다. 실차 연결 전 수명 주기·사용자 통제와 플랫폼 허용 범위를 정해야 한다.

일반 AAOS 시험 환경은 프로젝트 내 `.toolchains/android-uxprobe`와 `.android-user-home/uxprobe-avd`에 격리돼 있다. 실행 시 AVD와 SDK 환경변수는 해당 프로세스에만 설정한다. `carlog.isolatedUxProbe=true`로 빌드한 `kr.carlog.pleos.uxprobe`는 시험용 별도 앱 ID이며, 선택형 `standardAaosDrivingRestrictionProbe`는 `aaosUxProbe=true`와 에뮬레이터·초기 비제한 상태를 확인한 경우에만 주행 상태를 모의하고 종료 시 주차 상태로 되돌린다. 이 시험 옵션을 일반 APK에 적용하지 않는다.

Mock 수집 중단 버튼은 진행 중인 이벤트를 `interrupted`로 저장한다. 다시 시작하면 새 버퍼에서 수집하므로 중단 전 신호는 이후 이벤트에 포함되지 않는다. 이 제어는 현재 Mock에만 적용되며 실차 SDK의 동작을 의미하지 않는다.
