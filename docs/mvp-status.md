2026-11-09 SpeechToText 3.3.1은 공개 저장소에서 다운로드해 별도 실험 모듈에서 컴파일하고 전용 AVD에서 ON_DEVICE 초기화 성공과 해제 반환을 확인했다. 무음 PCM 시험은 15초 내 종료·오류 콜백이 없어 실패했으며 원인은 미확인이다. 마이크나 사용자 음성은 사용하지 않았다. FusedLocation 1.1.2 POM은 HTTP 404였지만 공식 한국어 문서의 1.1.3은 다운로드 가능했고, 별도 실험 모듈에서 전용 AVD의 `isSupported()`가 true이며 초기화·해제 호출이 반환됐다. 두 SDK의 앱 연결과 실차 지원은 미검증이다. 앞의 Playground 계정 표시는 다시 확인하지 않았다.

Android의 별도 음성 인식 앱을 사용자가 직접 여는 정차용 음성 명령 경로를 추가했다. 인식 앱 유무와 실제 음성 인식은 기기에서 검증하지 않았고 Pleos SpeechToText 연동은 아니다. 인식이 끝난 시점에 이벤트 저장을 요청한다.

FusedLocation 후속 시험에서 별도 시험 앱에 권한을 부여한 뒤 전용 AVD의 마지막 위치 콜백이 null이 아닌 것을 확인했다. 좌표 값·정확성·시각 의미는 검사하지 않았다. 앱 연동과 실차 지원은 아직 검증하지 않았다.

추가로 별도 앱 ID의 격리 계측 빌드에서 SDK 위치 콜백을 이벤트 버퍼·인메모리 Room·JSON에 전달했다. 에뮬레이터 좌표를 사용했고 SDK 시각 대신 수신 시각을 표기했다. 기본 앱 실차 연결, SDK 수명 주기 경합과 실차 지원은 미검증이다.

별도 Vehicle SDK 격리 계측 빌드에서도 에뮬레이터 주행거리 단발 조회를 이벤트 버퍼·인메모리 Room·JSON에 전달했다. SDK 콜백의 안전한 종료 계약은 확인되지 않아 기본 앱에 연결하지 않았으며 실차·연속 수집 시험이 아니다.

가장 큰 다음 단계는 Pleos 측에 [종료 계약 문의 초안](pleos-support-request.md)의 답을 확인하고, 확인된 SDK 기능만 별도 데이터 소스로 연결해 권한·실패·수명 주기와 실차 여부를 검증하는 것이다. 아직 문의는 자동 전송하지 않았다. 기존 웹 수정, 원격 push와 배포는 별도 사용자 지시 없이 수행하지 않는다.

## 공모전 초기 시연 범위 (2026-11-10 조정)

초기 완성은 정차 상태에서 Mock 데이터를 명확히 표시하며 이벤트 탭과 차량 관리 탭을 오가면서 주유·소모품 관리 → 이벤트 버튼 → 전후 기록 → 타임라인·그래프 → 정비 참고 리포트를 보여 주는 데 집중한다. 기존 구현의 동작을 유지하고, 화면에서 시연을 방해하는 문제와 빌드 실패만 우선 수정한다.

남은 우선 작업은 최신 빌드 확인, 주요 화면의 가독성과 버튼 동선 점검, 시연 환경에서 한 차례 전체 흐름 확인 및 시연 자료 정리다. 에뮬레이터는 확인할 때만 실행하고 종료한다. 전체 흐름은 이벤트 후 60초 수집을 포함한다.

실차 데이터 연동과 Pleos SDK의 안전한 수명 주기 검증, 주행 중 사용 승인, 자동 동기화와 PWA의 무손실 양방향 이관, 지도 내장 및 추가 기능 고도화는 이후 작업으로 미룬다. 현재 앱의 데이터는 시뮬레이션이며 실제 차량 데이터로 표시하지 않는다.

## 검증과 후속 작업

- 2026-11-11 HMI 개선: 이벤트 원터치·사후 분류, 차량 관리 카드, 테스트 도구와 Android Automotive UX 제한 상태 차단을 적용했다. 제한이 없다는 응답은 정차 여부를 증명하지 않는다. Pleos AVD에서 실제 제한 없는 초기 화면과 주입된 불명·제한 상태, 핵심 Mock 흐름을 확인했으며 실제 주행 전환과 실차는 미검증이다.
- 이벤트와 차량 관리를 별도 탭으로 분리한 뒤 전용 AVD에서 화면 배치, 탭 전환 중 Mock 신호 저장 및 주유·소모품부터 이벤트 전후 기록·리포트까지 통합 시험을 확인했다. 통합 시험은 인메모리 Room을 사용한다. 실제 차량·외부 지도 및 공유 앱은 미검증이다.
- 2026-11-10 Pleos 전용 AVD에서 주유·소모품 입력부터 Mock 이벤트 전후 수집, 그래프, 정비 결과 연결·리포트까지 포함한 통합 시연 계측 시험 1개가 통과했다. Mock과 인메모리 Room을 사용했으며 실차 데이터, 외부 지도·공유 앱, GUI 수동 시연을 확인한 결과는 아니다.
- `scripts/pleos-demo.sh`는 창 없는 모드에서 전용 AVD 부팅, 앱 설치·실행 상태 및 Ctrl+C 종료를 확인했다. 사용자가 워크스테이션에서 그래픽 창에 Carlog 화면이 표시되는 것을 확인했다. 그래픽 창에서의 전체 수동 시연과 실제 시연 기기의 설치·실행은 미검증이다. AVD는 읽기 전용이어서 종료 후 시연 입력은 보존되지 않는다.
- 2026-11-10 기본 앱 JVM 시험 160개와 Vehicle 17개·FusedLocation 2개·SpeechToText 1개 및 각 debug 빌드가 통과했다. Gradle 작업 139개 중 130개는 최신 상태를 재사용했다. JSON 예시와 잘못된 스키마 버전 검사도 통과했다. 이는 최신 전체 AVD 계측이나 실차 확인을 뜻하지 않는다.
- 2026-11-09 앱 JVM 테스트 147개와 SDK 실험 모듈 JVM 테스트 17개 및 debug 빌드가 통과했다. SDK JVM 시험과 일부 빌드는 Gradle 최신 상태 결과를 재사용했다. 전용 Pleos AVD의 기본 계측 결과 XML은 107개 중 통과 99개, 선택형 시험 8개 건너뜀, 실패 0개다. 건너뛴 항목은 주행 제한 2개, 2분 시연 1개, 공유·문서 선택기 진단 5개다. Gradle 종료 출력은 115개로 표시했지만 집계는 XML을 기준으로 했다.
- 이후 이벤트 복구와 관측값 변경을 포함해 앱 JVM 시험 150개·SDK 실험 모듈 JVM 시험 17개 및 debug 빌드를 다시 확인했다. 일부 작업은 최신 상태 결과를 재사용했다. 위 기본 계측 전체 결과는 그 이후 변경 전 실행 결과이며, 이후 변경은 관련 개별 계측 시험으로 확인했다.
- 이후 Pleos 전용 AVD 기본 계측을 다시 실행했다. XML 기준 앱은 110개 중 102개 통과·8개 건너뜀, 위치 실험 모듈은 4개 중 2개 통과·2개 건너뜀, 음성 실험 모듈은 2개 중 1개 통과·1개 건너뜀이고 실패는 없었다. 선택형 실험은 이 집계에서 검증한 것이 아니다.
- 정차 시연에서 사용하는 Mock 이벤트 전후 구간과 정비 결과 연결은 실제 경과 시간 시험으로 확인했다. 별도 UID의 테스트 수신 앱에 명시적으로 전달한 리포트·JSON 읽기도 확인했다. 전용 Pleos AVD의 공유 선택기 자동화 시도에서는 테스트 항목을 찾지 못했으며 원인은 미확인이다. 실차 데이터, Pleos 주행 제한의 실제 적용, 공유 선택기를 통한 실제 외부 앱별 파일 수신은 확인되지 않았다.
- 데이터 무결성은 같은 로컬 DB에서의 조건부 편집·삭제와 파일 가져오기 충돌 거부를 확인했다. 기기 간 동기화, PWA 백업의 무손실 가져오기, 실제 사용자 데이터 복원은 아직 검증하지 않았다.
- 사용자 계정의 SDK 접근 상태는 확인 시점의 표시다. 실제 차종별 권한과 지원 여부를 보장하지 않는다. 종료·콜백 계약에 대한 제공자의 답변과 권한 확인 전에는 실험 모듈을 앱 수집기에 연결하지 않는다.

## 2026-11-11 남은 UI 안내 과제

기존 전후 60초 수집 구현과 한계는 [README의 구현 범위](../README.md)와 [시연 문서](demo.md)에 이미 기록되어 있다. 이번 확인은 새 기능 구현이 아니다.

- 사전 확보 범위와 사후 수집 진행을 구분해 표시해야 한다. 현재 화면의 남은 시간은 사후 수집 대기 시간이며, 사전 데이터가 저장되지 않는 것으로 오인할 수 있다.
- 전체 차량 기록은 이벤트 목록과 별개인 주유·정비·지출 등의 관리 기록 목록이다. 현재 빈 목록에서도 제목만 노출되므로 빈 상태 안내와 기록 추가 동선을 보완해야 한다. 제목 자체는 버튼이 아니다. 아직 수정하지 않은 UI 과제다.
